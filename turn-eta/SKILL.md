# turn-eta — 이번 턴 얼마나 걸릴지 미리 말하기

작업을 시작하기 전에 "몇 스텝짜리고 몇 시에 끝날 것 같다"를 먼저 말하고, 끝나면 실제로 몇 분 걸렸는지를 남긴다. 그 기록이 쌓일수록 예상이 실제에 가까워진다.

## 언제 도나

**한 세션의 모든 턴 중, 실제 작업이 있는 턴마다.** 작업이란 파일을 고치거나, 명령을 돌리거나, 코드를 뒤져 조사하는 것.

- 작업이 있는 턴 → 작업을 시작하기 **전에** `plan`을 부르고, 그 턴 답변 **맨 마지막 문단**에 `예상 종료시각: 17:45`를 따로 한 줄로 적는다. 작업이 끝나면 `done`을 부른다.
- 대화만 하는 턴(질문에 답만 하거나, 무엇을 할지 의논만 하는 턴) → 아무것도 안 한다. 시끄럽기만 하다.
- 스텝이 하나뿐인 잔손질(한 줄 고치기 같은)도 굳이 돌리지 않는다.

## 어떻게 쓰나

스크립트는 `scripts/eta.js`, 순수 node라 설치할 게 없다. 이 스킬 폴더 기준 경로로 부른다.

**1. 작업 시작 전 — 몇 스텝인지 세고 예상을 낸다**

```
node <스킬폴더>/scripts/eta.js plan 4
```

찍히는 것:

```
4스텝 예정, 예상 16분 (스텝당 4분, 기본값 0건)
예상 종료시각: 17:45
(지난 6번 예상은 3분 낙관적)
```

이 중 `예상 종료시각: 17:45` 한 줄을 답변 맨 마지막 문단에 그대로 옮겨 적는다. 앞에 "4스텝 예정" 같은 말은 턴을 시작하는 문장에 자연스럽게 섞으면 돼.

**2. 그 턴의 작업이 끝나면**

```
node <스킬폴더>/scripts/eta.js done
```

```
예상 16분 / 실제 21분 (5분 낙관적)
```

id를 안 주면 그 프로젝트에서 마지막으로 연 기록을 닫는다. 여러 개가 겹칠 일이 있으면 `plan`이 준 id를 `done <id>`로 넘긴다.

**3. 지금 보정치가 궁금하면**

```
node <스킬폴더>/scripts/eta.js stats
```

## 예상이 정확해지는 방식

- 끝낸 기록이 **3건 미만**이면 스텝당 4분이라는 기본값으로 잡는다.
- 3건이 넘으면 기본값을 버리고 **실제로 걸린 시간의 스텝당 중앙값**을 쓴다. 평균이 아니라 중앙값이라 어쩌다 한 번 오래 걸린 턴이 전체를 밀어 올리지 않는다.
- 그 프로젝트 기록이 3건이 안 되면 다른 프로젝트 기록까지 합쳐 쓰고, 쌓이면 그 프로젝트 것만 쓴다. 프로젝트마다 한 스텝의 무게가 다르니까.
- 최근 20건까지만 본다. 옛날 습관이 계속 발목 잡지 않게.

## 기록이 쌓이는 곳

`~/.claude/turn-eta/log.tsv` — 홈에 쌓으니 프로젝트를 옮겨 다녀도 남는다. 줄마다 프로젝트 칸이 있어서 프로젝트별 보정이 따로 된다. 리포 안에는 아무것도 안 쌓는다.

`--log <경로>`로 다른 파일을 쓸 수 있고, `--project <이름>`으로 프로젝트 이름을 직접 줄 수도 있다(기본은 지금 폴더 이름).

## 확인

```
node <스킬폴더>/scripts/eta.js --selftest
```

`자체검증 통과`가 찍히면 된 거야.
