# show-me-your-eta

코딩 에이전트한테 "이거 언제 끝나?"를 매번 묻지 않아도 되게 만드는 스킬이다.

깔아 두면, 실제 작업이 있는 턴은 몇 스텝인지와 끝날 시각으로 시작해서 실제로 걸린 시간으로 끝난다.

> 네 스텝으로 할게 — 실패한 테스트 읽기, 파서 고치기, 픽스처 맞추기, 테스트 다시 돌리기.
>
> *…작업…*
>
> **예상 종료시각: 17:45**

스텝이 하나씩 끝날 때마다 실제로 몇 분 걸렸는지 재기 때문에, 초반부터 느린 턴은 끝나고서가 아니라
2스텝째에 그렇다고 말한다. 턴이 닫히면 예상과 실제가 기록에 남고, 다음 예상은 그 기록을 읽는다. 오래
쓸수록 숫자가 맞아 간다.

어느 에이전트든, 어느 프로바이더든, 어느 모델이든 쓴다.

[English](README.md) · **한국어**

## 설치

```bash
npx skills add 2JIHAN/show-me-your-eta
```

에이전트의 스킬 폴더에 깔린다 — Claude Code, Codex, Antigravity, Gemini CLI, Copilot CLI 등
[`skills`](https://skills.sh) CLI가 아는 곳이면 다 된다. 이 프로젝트만이 아니라 어디서나 쓰려면 `-g`를
붙인다.

그다음 `.gitignore`에 `.eta/`만 넣으면 끝이다(아래 참고). 받아 오는 의존성도, 빌드도, API 키도 없다.

내가 직접 칠 명령은 없다. 에이전트가 스킬을 읽고 알아서 부른다.

## 진짜로 걸리게 하기

깔면 설명은 에이전트가 찾을 수 있는 자리에 놓인다. 매 턴 그걸 집어 드는지는 에이전트에 달렸다. 클로드
코드에서는 `UserPromptSubmit` 훅이 확실하다.

```sh
#!/bin/sh
S="$CLAUDE_PROJECT_DIR/.claude/skills/turn-eta"
[ -f "$S/SKILL.md" ] || exit 0
echo "이번 턴에 실제 작업이 있으면 $S/SKILL.md 대로 한다 — 시작 전에 plan, 답변 마지막 문단에 예상 종료시각, 스텝이 끝날 때마다 step, 다 끝나면 done."
exit 0
```

`.claude/settings.json`의 `hooks.UserPromptSubmit`에 등록한다. 다른 에이전트에도 비슷한 자리가 있다.
훅 없이도 돌긴 하는데, 그러면 덜 걸린다.

## 무엇을 적어 두나

```
<프로젝트 루트>/.eta/
├── anthropic/
│   ├── claude-opus-5/log.tsv
│   └── claude-haiku-4-5/log.tsv
├── openai/
│   └── gpt-5-codex/log.tsv
└── google/
    └── gemini-3-pro/log.tsv
```

턴 하나가 한 줄이다. 몇 스텝이었는지, 얼마로 잡았는지, 실제로 얼마 걸렸는지, 스텝마다 몇 분씩 썼는지.

홈 폴더가 아니라 프로젝트 안에 두는 이유가 둘이다.

- **에이전트는 작업 폴더 밖으로 못 나가게 묶여 있는 경우가 많다.** 프로젝트 밖에 있는 기록은 못 읽는
  기록이고, 기록을 못 읽는 예상은 그냥 고정값이다.
- **모델마다 속도가 다르다.** 한 모델에서 잰 속도를 다른 모델에 그대로 갖다 쓰면 어긋난다. 폴더로 갈라
  두면 안 섞인다.

**`.gitignore`에 `.eta/`를 넣는다.** 내 컴퓨터에서 내 턴을 잰 값이라 같이 일하는 사람한테는 안 맞고,
턴마다 바뀌어서 커밋할 때마다 걸리적거린다.

## 예상이 좋아지는 방식

다음 예상은 **스텝당 실제 소요의 중앙값**이다. 좁은 것부터 보고, 끝난 기록이 3건 이상인 첫 칸에서
멈춘다.

| # | 단 | 여기까지 오는 때 |
|---|------|-----------|
| 1 | 이 프로바이더 + 모델 + 같은 크기 | 기록이 쌓이면 보통 여기 |
| 2 | 이 프로바이더 + 모델 | 그 크기를 해본 적이 별로 없을 때 |
| 3 | 이 프로바이더의 모든 모델 | 모델을 방금 바꿨을 때 |
| 4 | 이 프로젝트의 모든 기록 | 프로바이더를 방금 바꿨을 때 |
| 5 | `TURN_ETA_DIR` 공용 기록 | 새 프로젝트를 막 열었을 때 |
| 6 | 스텝당 4분 | 아직 아무 기록도 없을 때 |

평균이 아니라 중앙값이라, 어쩌다 한 번 길었던 턴이 그다음 예상을 전부 밀어 올리지 않는다. 각 단은 최근
20턴까지만 본다. 어느 단을 썼는지 같이 찍게 돼 있어서 숫자가 어디서 나왔는지 늘 보인다.

새 프로젝트가 예전 기록을 빌려 쓰게 하려면 `TURN_ETA_DIR`에 다른 `.eta` 폴더를 걸면 된다. 이 프로젝트
기록이 얇을 때만 본다.

## 고치고 싶다면

의존성 없는 node 스크립트 하나와 스킬 파일 하나가 전부다. 고친 걸 확인하려면:

```bash
node turn-eta/scripts/eta.js --selftest
```

경로 잡기, 프로바이더·모델 폴더 분기, 사다리 각 단, 스텝별 시간 재기, 공용 기록 빌려 쓰기를 덮는다.
테스트 도구는 안 쓴다. 이슈와 PR 환영.
